## Objetivo

Instalar Immich v3.3.3 en Docker aparte de AIO (HLD §6, §7, §9, ADR-011, ADR-012, ADR-013, ADR-026):
miniaturas, recodificados y base de datos en el SSD (`/srv/immich`), subidas de los móviles en
`Imagenes/Moviles` del pool, volcado diario de PostgreSQL a las 23:00 en `Archivo/immich-db`
(14 copias), biblioteca externa `Imagenes` en solo lectura sin `Moviles`, tareas nocturnas a las
00:00, primera clasificación con ML remoto en el PC de persona 1 y la Pi como URL de respaldo
(ADR-012, que el HLD v3 mantiene), app móvil con la URL local `http://192.168.1.11:2283` por la
Wi-Fi de casa (ADR-026) y la de Tailscale solo dentro del horario, y la limpieza
`immich-limpieza` a las 00:30 que solo archiva y añade al álbum «Revisar», sin permiso de borrado.
No es una fase de la guía: se numera 15 y se ejecuta tras los RBK 10 y 14 **y después del sync de
paridad** de la fase C del DCP-2026-10-15.

> Todas las órdenes son de **una línea** (`ssh nas "…"` o `ssh -t nas "…"`). No pegues varias
> líneas seguidas tras `ssh nas`. Los ficheros de configuración están ya en el repo en
> `state/config/` y se envían desde el PC con `cat state/config/<ruta> | ssh nas "sudo tee <ruta> >/dev/null"`.
> El compose se gestiona con `docker compose` por SSH (el plugin compose de OMV instala Docker
> pero no tiene carpeta compartida configurada; igual que AIO en el RBK 10 v3).

## Prerrequisitos

- [ ] RBK 10 v3 y RBK 14 completados (Docker, pool y Tailscale)
- [ ] DCP-2026-10-15 fase C cerrada: sync de paridad completo y `snapraid status` sin errores (paso 1)
- [ ] Backup restic al día (HLD §7)
- [ ] Contraseña de la base de datos de Immich (solo `A-Za-z0-9`) y del admin de Immich creadas en el gestor de contraseñas
- [ ] PC de persona 1 con Docker Desktop instalado para el ML remoto
- [ ] Ficheros en el repo: `state/config/srv/immich/compose/docker-compose.yml`,
      `state/config/srv/immich/compose/env.sin-secretos`, `state/config/usr/local/sbin/immich-limpieza`,
      `state/config/etc/systemd/system/immich-limpieza.service` y `.timer`

### Paso 1: Comprobar paridad, pool, Docker y puerto

| Campo | Valor |
|---|---|
| **Riesgo** | Lectura |
| **Ejecuta** | Agente |
| **Dónde** | NAS por SSH |
| **HLD** | §5, §6, §7 |

Comando:

```bash
ssh nas "findmnt -n /srv/mergerfs/pool && sudo snapraid status | tail -n 15 && sudo docker compose version && df -h / && (sudo ss -ltnp | grep ':2283 ' || echo 'puerto 2283 libre')"

Esperado: pool montado; `snapraid status` sin errores ni bloques sin sincronizar (`No error detected`

`puerto 2283 libre`.

Si falla: si la paridad no está sincronizada, para: esta fase va después del sync de la fase C del
DCP-2026-10-15. Si falta `docker compose`, vuelve al paso 3 del RBK 10 v3.

ssh nas "sudo systemd-analyze verify /etc/systemd/system/immich-limpieza.service /etc/systemd/system/immich-limpieza.timer && sudo grep -c '^OnCalendar=' /etc/systemd/system/immich-limpieza.timer && sudo systemctl daemon-reload && sudo systemctl enable --now immich-limpieza.timer && systemctl list-timers immich-limpieza.timer --no-pager"
```

Esperado: `systemd-analyze verify` sin errores; `1` (un solo `OnCalendar`); `immich-limpieza.timer`

## Vuelta atrás

- Limpieza: `/var/log/immich-limpieza.log` guarda cada ID con fecha. Para deshacer una ejecución,
  quitar esos ID del álbum «Revisar» y devolverlos a la línea de tiempo (en la web de Immich:
  Archivo → seleccionar → Desarchivar; o con la API `PUT /api/assets` con `visibility: timeline`).
  Desactivar: `ssh nas "sudo systemctl disable --now immich-limpieza.timer"`.

  Las fotos de `Imagenes/Moviles` y los volcados quedan en el pool; `/srv/immich` (miniaturas y
  base de datos) se puede borrar a mano (lo hace el usuario: `rm -r` está bloqueado para el agente).
